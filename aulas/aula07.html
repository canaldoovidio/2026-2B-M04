A Aula 06 deixou o evento do ciclo publicado em JSON

O rastreador já publica o evento do ciclo no broker MQTT. O dado só chega a quem acompanha pelo escritório; na oficina, ao lado do equipamento, a pessoa precisa de uma saída local.

O TAPI pede bateria, última comunicação e estado do lacre visíveis. Hoje o dispositivo ganha duas saídas locais: um display LCD de 16 por 2 ligado por I2C e o LED de status com brilho controlado por PWM.

Pergunta disparada: o que cabe numa tela de 16 por 2 caracteres? O que fica de fora, e onde a pessoa da oficina encontra o que ficou de fora?

A resposta é a decisão humana da etapa SP3 do DAIA-E nesta aula: o que o dispositivo mostra localmente.

O PWM liga e desliga o pino rápido demais para o olho

Pense num ventilador que fica ligado 15 minutos a cada hora. Na média, ele trabalhou um quarto do tempo. O PWM faz o mesmo com o pino, só que milhares de vezes por segundo.

O ciclo de trabalho é a fração de cada período em que o pino fica em 3,3 V. A tensão média é Vmédia = ciclo × 3,3 V.

No laboratório o PWM roda a 5 000 Hz: cada período dura 1 / 5 000 s = 200 µs.

Com 8 bits de resolução, a base do ciclo é 256: o valor 64 dá 64 / 256 = 25% e o valor 128 dá 128 / 256 = 50%. 255 é o máximo do 8 bits (99,6%).

A 50% de ciclo, o brilho percebido chega a L* de 76

Ciclo de trabalhoTensão médiaLuminosidade percebida (L*, de 0 a 100)
10%0,33 V38
25%0,83 V57
50%1,65 V76

De 25% a 50% de ciclo, a tensão média dobra (0,83 V para 1,65 V) e o L* sobe de 57 para 76. L* é a luminosidade CIE 1976 do espaço CIELAB, L* = 116 × Y1/3 − 16, com Y tomado igual ao ciclo. O LED do Wokwi aplica correção gama de 2,8 por padrão.

ledcAttach configura o PWM no core 3.x

const int PINO_LED = 2;

void setup() {
  // pino, frequência em Hz, resolução em bits
  ledcAttach(PINO_LED, 5000, 8);
}

void loop() {
  ledcWrite(PINO_LED, 64);    // 25%
  delay(1000);
  ledcWrite(PINO_LED, 255);   // 99,6%
  delay(1000);
}

O laboratório compila com o core esp32:esp32 3.3.12. No core 3.x, ledcAttach(pino, frequência, resolução) escolhe o canal sozinho e ledcWrite recebe o pino.

ledcSetup e ledcAttachPin, do core 2.x, foram removidas (guia de migração da Espressif). Código copiado de tutorial antigo não compila.

analogWrite(pino, 0 a 255) também existe no core 3.x.

No I2C, dois fios atendem até 112 endereços

Pense na chamada da sala: o professor diz um número e só o aluno com aquele número responde. No I2C, o ESP32 é o professor, os fios SDA (dados) e SCL (relógio) são a sala, e cada dispositivo tem um endereço de 7 bits.

Quem reconhece o próprio endereço responde com ACK. Se ninguém tem o endereço, o ESP32 lê NACK.

DispositivoEndereçoFonte
LCD com PCF85740x20 a 0x27datasheet NXP, seção 7.1
LCD com PCF8574A0x38 a 0x3Fdatasheet NXP, seção 7.1
LCD no Wokwi0x27peça wokwi-lcd1602
MPU6050 da Aula 050x68peça wokwi-mpu6050

A varredura vai de 0x08 a 0x77: 112 endereços. Os outros 16 são reservados (especificação I2C NXP UM10204, seção 3.1.12).

Confronto com a IA: o endereço do LCD

  1. Cada dupla pergunta ao Gemini: "Qual é o endereço I2C de um LCD 16x2 com módulo PCF8574?"
  2. Coloque o endereço sugerido em ENDERECO_LCD e rode o laboratório.
  3. Compare com a varredura do monitor serial e com a seção 7.1 do datasheet do PCF8574.
  4. A turma classifica cada resposta: confirmada, ajustada ou errada, com a evidência. Uma resposta rejeitada ou corrigida vira o ADR da dupla.
  5. Veredito com a fonte primária para "0x3F": ajustada. 0x3F vale para o PCF8574A e 0x27 para o PCF8574 (datasheet NXP, seção 7.1); a varredura mostra qual chip está no módulo.

Verificação: endereço I2C

A varredura mostrou 0x27 e 0x68. O código usa ENDERECO_LCD = 0x3F. O que acontece?

  • O MPU6050 recebe o texto no lugar do LCD
  • O display fica sem texto e a serial avisa que nada respondeu em 0x3F
  • O LCD responde, porque 0x3F e 0x27 são do mesmo tipo de módulo
  • O código não compila
