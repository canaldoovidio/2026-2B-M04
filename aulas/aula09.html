A Aula 08 deixou o RSSI no dashboard

O rastreador já publica via MQTT o RSSI em dBm e a última comunicação, e o dashboard mostra os dois.

Hoje o alerta deixa de ser só leitura: o alerta de permanência (referência inicial de 150 dias no TAPI) ou de violação do lacre aciona um atuador remoto, um relé que liga o sinalizador da Gestão Patrimonial.

No conjunto fictício do case, o ciclo CI-003 está há 190 dias fora em 01/10/2026, 40 acima do limiar (dados/ciclos.csv).

O relé só liga com confirmação humana num segundo tópico; sem ela, desarma em 30 s.

O relé liga em um único lugar do código

void tratarConfirmacao(const String& texto) {
  // ... DESLIGAR tratado antes
  if (estado != ARMADO ||
      texto != "CONFIRMAR " + String(idArmado)) {
    publicarEstado("confirmação ignorada ...");
    return;
  }
  digitalWrite(PINO_RELE, RELE_LIGADO);
  estado = DISPARADO;
}

O alerta só arma a central. Ligar o relé exige estado armado e o id do alerta em vigor.

No loop, armado há 30 s sem confirmação volta a monitorar: desarme automático.

Confronto com a IA: o código de disparo

  1. Cada dupla pede ao Gemini um sketch para ESP32 que ligue um relé quando chegar uma mensagem MQTT.
  2. Marquem cada digitalWrite que liga o relé e a mensagem que leva até ele.
  3. Classifiquem: o código dispara sem confirmação, com confirmação sem id ou com confirmação válida?
  4. Procurem também o estado do relé no setup e o que acontece se o Wi-Fi cair com o relé ligado.
  5. Registrem como confirmada, ajustada ou errada, etapa Confrontar do 5C. Uma rejeição vira o ADR.
