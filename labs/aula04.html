Laboratório: o rastreador guarda 8 eventos sem conexão e os entrega na ordem

O TAPI da Cerradinho pede armazenamento de eventos e envio posterior em caso de indisponibilidade de conexão. Aqui o botão gera um evento (um rompimento do lacre), a chave deslizante faz o papel da conexão, e um vetor de 8 posições com dois ponteiros guarda os eventos até a conexão voltar. A serial imprime o endereço de cada posição, que você usa para conferir a aritmética de ponteiros. O laboratório roda no Wokwi com ESP32 e segue as cinco etapas do 5C no seu PROCESSO.md.

  1. Abra wokwi.com/projects/new/esp32.
  2. Na aba diagram.json, apague tudo e cole o circuito abaixo: botão de evento no GPIO 4, chave de conexão no GPIO 18, LED verde de conexão no GPIO 23 e LED vermelho de buffer cheio no GPIO 22.

  4. Inicie a simulação e abra o monitor serial. A chave começa à direita, sem conexão. Arraste a chave para a esquerda para a conexão voltar.

Código (labs/aula04/sketch.ino) 

// Aula 04: buffer circular de eventos do rastreador da Cerradinho.
// O TAPI pede armazenamento de eventos e envio posterior quando falta conexão.
// O botão gera um evento (um rompimento do lacre); a chave deslizante simula a
// conexão. Sem conexão, o evento fica no buffer; quando a conexão volta, os
// eventos saem na ordem em que chegaram. A serial imprime o endereço de cada
// posição para conferir a aritmética de ponteiros.
const int PINO_EVENTO = 4;          // botão até o GND, com pull-up interno
const int PINO_CONEXAO = 18;        // chave: ligada ao GND = conexão disponível
const int PINO_LED_CONEXAO = 23;
const int PINO_LED_CHEIO = 22;
const int CAPACIDADE = 8;
const bool DESCARTAR_MAIS_ANTIGO = true;   // decisão do grupo, registrada em ADR
const unsigned long JANELA_DEBOUNCE_MS = 20;
const unsigned long INTERVALO_ENVIO_MS = 500;

struct Evento {
  uint32_t sequencia;               // número do evento, em ordem de chegada
  uint32_t instanteMs;              // millis() no momento do evento
};

Evento buffer[CAPACIDADE];
Evento *escrita = buffer;           // onde o próximo evento será guardado
Evento *leitura = buffer;           // o evento mais antigo ainda não enviado
int guardados = 0;
uint32_t proximaSequencia = 1;

int nivelAnterior = HIGH;
int estadoEstavel = HIGH;
unsigned long ultimaMudancaMs = 0;
unsigned long ultimoEnvioMs = 0;
bool conectadoAntes = false;

Evento *avancar(Evento *p) {
  p++;                              // anda sizeof(Evento) bytes na memória
  if (p == buffer + CAPACIDADE) {   // passou da última posição: dá a volta
    p = buffer;
  }
  return p;
}

void guardar(unsigned long agora) {
  uint32_t numero = proximaSequencia++;
  if (guardados == CAPACIDADE) {
    if (!DESCARTAR_MAIS_ANTIGO) {
      Serial.printf("Buffer cheio: evento %lu descartado\n", (unsigned long)numero);
      return;
    }
    Serial.printf("Buffer cheio: evento %lu sobrescrito\n", (unsigned long)leitura->sequencia);
    leitura = avancar(leitura);
    guardados--;
  }
  escrita->sequencia = numero;
  escrita->instanteMs = agora;
  Serial.printf("Evento %lu guardado em buffer[%d], endereço %p\n",
                (unsigned long)numero, (int)(escrita - buffer), (void *)escrita);
  escrita = avancar(escrita);
  guardados++;
}

void enviar() {
  Serial.printf("Enviado evento %lu, de buffer[%d] (instante %lu ms)\n",
                (unsigned long)leitura->sequencia, (int)(leitura - buffer),
                (unsigned long)leitura->instanteMs);
  leitura = avancar(leitura);
  guardados--;
}

void setup() {
  pinMode(PINO_EVENTO, INPUT_PULLUP);
  pinMode(PINO_CONEXAO, INPUT_PULLUP);
  pinMode(PINO_LED_CONEXAO, OUTPUT);
  pinMode(PINO_LED_CHEIO, OUTPUT);
  Serial.begin(115200);
  Serial.printf("sizeof(int) = %d, sizeof(Evento) = %d bytes\n", (int)sizeof(int), (int)sizeof(Evento));
  for (int i = 0; i < CAPACIDADE; i++) {
    Serial.printf("buffer[%d] em %p\n", i, (void *)(buffer + i));
  }
  Serial.printf("Memória livre no heap: %lu bytes\n", (unsigned long)ESP.getFreeHeap());
  Serial.println("Rastreador pronto. Botão: evento. Chave: conexão.");
}

void loop() {
  unsigned long agora = millis();

  int nivel = digitalRead(PINO_EVENTO);     // debounce da Aula 02
  if (nivel != nivelAnterior) {
    ultimaMudancaMs = agora;
    nivelAnterior = nivel;
  }
  if (agora - ultimaMudancaMs >= JANELA_DEBOUNCE_MS && nivel != estadoEstavel) {
    estadoEstavel = nivel;
    if (estadoEstavel == LOW) guardar(agora);
  }

  bool conectado = digitalRead(PINO_CONEXAO) == LOW;
  if (conectado != conectadoAntes) {
    Serial.println(conectado ? "Conexão voltou" : "Conexão caiu");
    conectadoAntes = conectado;
  }
  if (conectado && guardados > 0 && agora - ultimoEnvioMs >= INTERVALO_ENVIO_MS) {
    enviar();
    ultimoEnvioMs = agora;
  }

  digitalWrite(PINO_LED_CONEXAO, conectado ? HIGH : LOW);
  digitalWrite(PINO_LED_CHEIO, guardados == CAPACIDADE ? HIGH : LOW);
}

Os pinos escolhidos evitam três grupos que o datasheet do ESP32 restringe: GPIO 34 a 39 só leem e não têm pull-up interno, GPIO 6 a 11 ficam reservados à memória flash e GPIO 0, 2, 5, 12 e 15 definem a configuração de boot. Na chave deslizante do Wokwi, o pino 2 é o comum: com a alavanca à esquerda ele encosta no pino 1, ligado ao GND, e o GPIO 18 lê LOW. O atributo bounce em 0 desliga o bounce simulado da chave.

2. Contextualizar

Antes de mexer no código, escreva no PROCESSO.md:

  • o objetivo: nenhum evento gerado sem conexão se perde enquanto o buffer tem espaço, e todos saem na ordem de chegada quando a conexão volta;
  • a sua previsão: depois de 10 eventos sem conexão num buffer de 8 posições, em que posição está o ponteiro de escrita, quais eventos continuam guardados e quais se perderam;
  • a sua previsão da distância, em bytes, entre os endereços de buffer[0] e buffer[1];
  • o critério de aceitação: com a conexão de volta, a serial mostra os eventos guardados em ordem crescente de número, sem repetição;
  • o que você pretende delegar à IA e o que pretende fazer sozinho.

3. Consultar

Faça ao Gemini uma pergunta delimitada, que peça explicação ou hipótese sobre um ponto que você não domina. Exemplos:

  • "Em C++, se p é um ponteiro para uma struct de dois uint32_t, quanto o endereço muda em p + 1, e por quê?"
  • "Como um buffer circular sabe que está cheio quando os ponteiros de escrita e de leitura apontam para a mesma posição?"

Registre a pergunta exatamente como você fez e a resposta resumida.

4. Confrontar

Confira a explicação da IA contra o que o ESP32 imprime. No início da simulação, a serial mostra sizeof(Evento) e o endereço de cada posição do buffer. Preencha:

PosiçãoEndereço impressoDiferença para a posição anterior (bytes)Previsto pela IA
buffer[0]n/a
buffer[1]
buffer[2]
buffer[7]

Os endereços aparecem em hexadecimal: a diferença entre 0x3ffb2a10 e 0x3ffb2a18, por exemplo, é 8. Os endereços reais do seu buffer serão outros. Diga se a explicação da IA se confirmou, precisou de ajuste ou estava errada. Depois gere 10 eventos sem conexão e compare a sua previsão da etapa Contextualizar com a serial. Se você rejeitou ou corrigiu a explicação, ela vira o seu ADR.

5. Construir

Mude DESCARTAR_MAIS_ANTIGO para false, repita os 10 eventos e anote quais se perdem agora. Versione no repositório do grupo o sketch.ino, o diagram.json, o link do projeto salvo no Wokwi, a tabela da etapa Confrontar e duas capturas do monitor serial, uma com cada política. A política que o grupo escolher para o protótipo físico offline vira o ADR do grupo.

6. Comprovar

Sem consultar a IA, responda no PROCESSO.md:

  1. Por que escrita++ anda 8 bytes na memória?
  2. O que aconteceria sem o if (p == buffer + CAPACIDADE) da função avancar, no nono evento?
  3. Com a política de descartar o mais antigo, um rompimento do lacre ocorrido no primeiro dia sem conexão chega à Cerradinho? Em que condição ele se perde?

7. Desafio: contador de eventos perdidos

O rastreador precisa avisar quando perdeu informação. Acrescente um contador de eventos perdidos, que soma um a cada evento descartado com o buffer cheio, nas duas políticas. Quando a conexão voltar, envie primeiro uma linha Perdidos: N e só depois os eventos guardados, e zere o contador depois do envio.
