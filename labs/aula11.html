Laboratório: o rastreador publica pela porta 8883 sem senha no código

Até aqui o rastreador publicava o evento do ciclo na porta 1883, em texto claro, com a configuração escrita no próprio sketch. Hoje ele ganha três defesas: TLS com o certificado do broker verificado, usuário e senha no CONNECT e credenciais num arquivo secrets.h que nunca vai para o repositório. O laboratório roda no Wokwi com ESP32 e segue as cinco etapas do 5C no seu PROCESSO.md.

1. Abrir o projeto no Wokwi

  1. Abra wokwi.com/projects/new/esp32.
  2. Na aba diagram.json, apague tudo e cole o circuito abaixo: botão do lacre no GPIO 4 e LED de sessão TLS no GPIO 2, com resistor de 220 Ω.
  3. Na aba sketch.ino, apague tudo e cole o código abaixo.
  4. Crie a aba libraries.txt (menu do editor, novo arquivo) com a biblioteca abaixo. O Wokwi instala o que estiver listado nela.
  5. Crie a aba secrets.h com o modelo abaixo e troque usuário e senha pelos da sua dupla. Este arquivo é o único lugar onde a senha aparece.
  6. Troque dupla00 no tópico pelo número da sua dupla, inicie a simulação e abra o monitor serial.

// Aula 11: o rastreador da Cerradinho publica o evento do ciclo por MQTT com TLS
// (porta 8883), entra no broker com usuário e senha e não guarda credencial no
// código. As credenciais ficam em secrets.h, uma aba do projeto no Wokwi que
// nunca vai para o repositório (entra no .gitignore). Sem secrets.h o sketch
// compila com valores de exemplo e avisa na serial.
#include <WiFi.h>
#include <WiFiClientSecure.h>
#include <PubSubClient.h>

#if __has_include("secrets.h")
#include "secrets.h"
#define CREDENCIAIS_DE_EXEMPLO 0
#else

WiFiClientSecure redeSegura;
PubSubClient mqtt(redeSegura);

int leituraAnterior = HIGH;
int estadoEstavel = HIGH;
unsigned long ultimaMudancaMs = 0;
unsigned long violacoes = 0;

void conectarWiFi() {
  WiFi.begin(WIFI_SSID, WIFI_SENHA, 6);       // Wokwi-GUEST fica no canal 6
  Serial.print("Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(250);
    Serial.print(".");
  }
  Serial.println(" conectado");
}

void conectarBroker() {
  while (!mqtt.connected()) {
    String id = "m04-dv01-" + String(esp_random(), HEX);
    Serial.print("Broker TLS na porta 8883... ");
    if (mqtt.connect(id.c_str(), MQTT_USUARIO, MQTT_SENHA)) {
      Serial.println("conectado, certificado verificado contra a CA raiz");
    } else {
      Serial.print("falhou, state = ");       // -2: conexão ou handshake TLS falhou
      Serial.println(mqtt.state());           // 4: usuário ou senha recusados
      delay(2000);
    }
  }
}

void publicarEvento(const char* tipo) {
  // Valores fictícios de dados/leituras.csv (CI-003, leitura de 30/09/2026).
  char payload[200];
  snprintf(payload, sizeof(payload),
           "{\"dispositivo\":\"DV-01\",\"ciclo\":\"CI-003\",\"nf\":\"NF-R-10021\","
           "\"evento\":\"%s\",\"x_km\":40.27,\"y_km\":24.71,\"bateria_pct\":43,\"violacoes\":%lu}",
           tipo, violacoes);
  bool ok = mqtt.publish(TOPICO, payload);
  Serial.print(ok ? "Publicado: " : "Falha ao publicar: ");
  Serial.println(payload);
}

void setup() {
  Serial.begin(115200);
  pinMode(PINO_LACRE, INPUT_PULLUP);
  pinMode(PINO_LED, OUTPUT);
  if (CREDENCIAIS_DE_EXEMPLO) {
    Serial.println("Aviso: secrets.h ausente, usando credenciais de exemplo.");
  }
  conectarWiFi();
  redeSegura.setCACert(CA_RAIZ);              // sem isto não há verificação do broker
  mqtt.setServer(MQTT_HOST, MQTT_PORTA_TLS);
  conectarBroker();
  publicarEvento("ligado");
}

void loop() {
  if (!mqtt.connected()) conectarBroker();
  mqtt.loop();
  digitalWrite(PINO_LED, mqtt.connected() ? HIGH : LOW);

  int leitura = digitalRead(PINO_LACRE);      // debounce da Aula 02
  if (leitura != leituraAnterior) {
    ultimaMudancaMs = millis();
    leituraAnterior = leitura;
  }
  bool estavel = millis() - ultimaMudancaMs >= JANELA_DEBOUNCE_MS;
  if (estavel && leitura != estadoEstavel) {
    estadoEstavel = leitura;
    if (estadoEstavel == LOW) {
      violacoes++;
      publicarEvento("violacao_lacre");
    }
  }
}

secrets.h

O sketch usa __has_include("secrets.h"): com o arquivo presente, as credenciais vêm dele; sem o arquivo, o código compila com valores de exemplo e avisa na serial. É assim que o acervo compila o laboratório no CI sem nenhuma senha.

Duas consequências. Primeira: no broker público, o usuário e a senha configurados hoje não protegem nada, porque qualquer senha entra. O laboratório treina a configuração; a autenticação de fato depende do broker de sala, ainda não definido (pendência P7). Segunda: a conexão TLS foi conferida pelo acervo a partir de um computador, e a execução dentro do Wokwi não foi conferida. Se o handshake falhar no simulador com a CA certa, registre a mensagem da serial no Comprovar e rode o mesmo sketch no ESP32 do kit.

3. Contextualizar

Antes de mexer no código, escreva no PROCESSO.md:

  • o modelo de ameaça desta etapa: quem é o atacante (alguém na mesma rede do rastreador, alguém com acesso ao repositório público), o que ele quer (ler a localização e a NF, publicar evento falso) e a que ele tem acesso;
  • o comportamento esperado: a serial mostra conectado, certificado verificado contra a CA raiz e cada aperto do lacre publica um evento;
  • o critério de aceitação: nenhuma senha aparece em arquivo versionado, e trocar a CA por outra faz a conexão falhar;
  • o que você pretende delegar à IA e o que pretende fazer sozinho.

4. Consultar

Faça ao Gemini uma pergunta delimitada sobre um ponto que você não domina. Exemplos:

  • "No ESP32 com Arduino, o que o método setCACert do WiFiClientSecure verifica durante a conexão?"
  • "Que certificado de CA devo usar para conectar ao broker.hivemq.com na porta 8883?"

Registre a pergunta exatamente como você fez e a resposta resumida.

6. Construir

Versione no repositório do grupo o sketch.ino, o diagram.json, o libraries.txt, o secrets.exemplo.h, a linha do .gitignore, o link do projeto salvo no Wokwi e uma captura do monitor serial com a conexão e um evento publicado. O secrets.h com a senha real não entra.

O Wokwi salva todas as abas do projeto, inclusive o secrets.h. Um projeto salvo como público expõe a senha a quem tiver o link: para o repositório, compartilhe o projeto sem a aba de credenciais.

7. Comprovar

Sem consultar a IA, responda no PROCESSO.md:

  1. Com o secrets.h em uso, em que lugar a senha ainda fica legível, e para quem?
  2. Com TLS ligado, quem continua lendo o evento publicado no tópico do broker público?
  3. Comentando a linha do setCACert, o que aparece na serial, e por quê?
  4. O handshake TLS funcionou no Wokwi? Cole a linha da serial que comprova.

8. Desafio: leitura e escrita separadas por tópico

O rastreador só precisa publicar o próprio evento e ler um tópico de comando. O BI só precisa ler. Escreva a lista de controle de acesso (ACL) do broker no formato do acl_file do Mosquitto, em que user abre o bloco de um usuário e topic read, topic write ou topic readwrite dão a permissão por tópico:

  • o usuário de cada rastreador escreve só em .../DV-01/evento e lê só em .../DV-01/comando;
  • o usuário do BI lê os eventos de todos os rastreadores e não escreve em nada;
  • explique, com o modelo de ameaça do Contextualizar, qual ataque cada linha bloqueia.

No broker público as permissões não valem. A ACL vira entrega da Arquitetura refinada da solução e passa a valer no broker de sala, quando a pendência P7 for resolvida.
