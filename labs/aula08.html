Módulo 04 IN · Aula 08 · 27/11/2026 · Sprint 4 · ESP32

Laboratório: o rastreador publica o próprio sinal em dBm

O TAPI da Cerradinho pede que a interface mostre a última comunicação de cada rastreador e que a equipe teste as limitações de comunicação em ambientes cobertos. Aqui o ESP32 lê o RSSI, converte para miliwatt, publica um JSON por MQTT e o painel da Aula 08 desenha a série tempo por dBm. O código e o MQTT são testados no Wokwi; o sinal que varia é medido na bancada, com o ESP32 do kit. Registre as cinco etapas do 5C no seu PROCESSO.md.

1. Abrir o projeto no Wokwi

  1. Abra wokwi.com/projects/new/esp32.
  2. Na aba diagram.json, apague tudo e cole o circuito abaixo: ESP32 DevKitC e o LED de MQTT no GPIO 2, com resistor de 220 Ω.
  3. Crie a aba libraries.txt (no menu do Library Manager do Wokwi) e cole a lista de bibliotecas.
  4. Na aba sketch.ino, apague tudo, cole o código e troque ID_DUPLA pelo identificador da sua dupla.
  5. Inicie a simulação e abra o painel com a mesma dupla. O LED acende quando o MQTT conecta.

Código (labs/aula08/sketch.ino) 

// Aula 08: o rastreador da Cerradinho mede o RSSI em dBm e publica por MQTT.
// A cada INTERVALO_MS: lê WiFi.RSSI(), converte para mW, imprime na serial e
// publica um JSON no tópico PREFIXO_TOPICO/<dupla>/<dispositivo>/rssi.
// O status online/offline fica retido no broker; o offline é o "last will", que
// o broker publica sozinho quando o rastreador some (o elevador da ponderada).
// No Wokwi a rede é a Wokwi-GUEST; na bancada, troque SIMULADOR para 0.
#include <WiFi.h>
#include <PubSubClient.h>
#include <math.h>

#define SIMULADOR 1                            // 1 no Wokwi, 0 na bancada com o ESP32 do kit
const char* REDE_SALA = "nome-da-rede";        // só na bancada; credencial fora do código é tema da Aula 11
const char* SENHA_SALA = "senha-da-rede";

const char* BROKER = "broker.hivemq.com";      // broker público (P7: broker de sala não definido)
const int PORTA = 1883;
const char* PREFIXO_TOPICO = "inteli-m04/t24";
const char* ID_DUPLA = "dupla00";              // troque pelo identificador da sua dupla
const char* ID_DISPOSITIVO = "DV-01";
const unsigned long INTERVALO_MS = 2000;       // decisão humana: na Cerradinho o TAPI pede semanal
const int PINO_LED = 2;                        // aceso enquanto o MQTT está conectado

WiFiClient rede;
PubSubClient mqtt(rede);
char topicoRssi[96];
char topicoStatus[96];
unsigned long ultimoEnvioMs = 0;
unsigned long ultimaTentativaMs = 0;
unsigned long sequencia = 0;

void conectarWiFi() {
#if SIMULADOR
  WiFi.begin("Wokwi-GUEST", "", 6);            // canal 6 pula a busca de redes no Wokwi
#else
  WiFi.begin(REDE_SALA, SENHA_SALA);
#endif
  Serial.print("Conectando ao Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(250);
    Serial.print(".");
  }
  Serial.println(" conectado.");
}

void conectarMqtt() {
  char idCliente[48];
  snprintf(idCliente, sizeof(idCliente), "%s-%s-%04lx", ID_DUPLA, ID_DISPOSITIVO, (unsigned long)(esp_random() & 0xffff));
  // Último desejo: QoS 1 e retido, para o painel saber que o rastreador sumiu.
  if (mqtt.connect(idCliente, topicoStatus, 1, true, "offline")) {
    mqtt.publish(topicoStatus, "online", true);
    Serial.print("MQTT conectado. Publicando em ");
    Serial.println(topicoRssi);
  } else {
    Serial.print("MQTT falhou, estado ");
    Serial.println(mqtt.state());
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(PINO_LED, OUTPUT);
  snprintf(topicoRssi, sizeof(topicoRssi), "%s/%s/%s/rssi", PREFIXO_TOPICO, ID_DUPLA, ID_DISPOSITIVO);
  snprintf(topicoStatus, sizeof(topicoStatus), "%s/%s/%s/status", PREFIXO_TOPICO, ID_DUPLA, ID_DISPOSITIVO);
  conectarWiFi();
  mqtt.setServer(BROKER, PORTA);
  mqtt.setKeepAlive(5);                         // o broker declara offline em cerca de 1,5 × 5 s
}

void loop() {
  if (!mqtt.connected() && millis() - ultimaTentativaMs >= 5000) {
    ultimaTentativaMs = millis();
    if (WiFi.status() == WL_CONNECTED) conectarMqtt();
    else Serial.println("Sem Wi-Fi: leitura não enviada.");
  }
  mqtt.loop();
  digitalWrite(PINO_LED, mqtt.connected() ? HIGH : LOW);

  if (millis() - ultimoEnvioMs < INTERVALO_MS) return;
  ultimoEnvioMs = millis();
  if (WiFi.status() != WL_CONNECTED) return;

  long rssi = WiFi.RSSI();                      // dBm da última comunicação com o ponto de acesso
  double miliwatts = pow(10.0, rssi / 10.0);    // dBm = 10 × log10(P / 1 mW)
  sequencia++;
  Serial.printf("RSSI %ld dBm = %.2e mW\n", rssi, miliwatts);

  char json[128];
  snprintf(json, sizeof(json), "{\"dispositivo\":\"%s\",\"seq\":%lu,\"rssi_dbm\":%ld,\"uptime_s\":%lu}",
           ID_DISPOSITIVO, sequencia, rssi, millis() / 1000);
  if (mqtt.connected()) mqtt.publish(topicoRssi, json);
}

O Wokwi oferece um ponto de acesso virtual, o Wokwi-GUEST, aberto e no canal 6. A documentação do simulador não descreve modelo de sinal: nem o Wokwi-GUEST nem a peça de ponto de acesso personalizado têm atributo de intensidade, e o simulador não simula distância, parede ou elevador. O RSSI que aparece na serial do Wokwi prova só que a leitura e a publicação funcionam; não espere ver o número mudar. A variação de sinal da ponderada é medida na bancada, com SIMULADOR em 0 e o ESP32 do kit na rede da sala.

2. Contextualizar

Antes de medir, escreva no PROCESSO.md:

  • o objetivo: o painel mostra a série tempo por dBm e a última comunicação, e registra o sumiço do rastreador dentro do elevador;
  • a ordem em que você espera encontrar os cinco pontos do seu percurso, do sinal mais forte ao mais fraco, justificada por distância até o roteador, obstáculos e material das paredes;
  • a diferença em dB que você considera perceptível entre dois pontos;
  • o que pretende delegar à IA e o que pretende fazer sozinho.

O percurso de cada aluno é definido pelo último dígito do RA, numa tabela que o enunciado manda publicar no card do encontro. Essa tabela ainda não existe (pendência P6 do plano de ensino). Até ela sair, este laboratório não define percurso; o último ponto de qualquer percurso é o interior do elevador, como diz o enunciado.

3. Consultar

Pergunte ao Gemini como se estima distância a partir do RSSI e quais premissas o modelo assume. Registre a pergunta exatamente como fez, o modelo que a IA apresentou (fórmula e constantes) e cada premissa que ela declarou.

4. Construir

  1. No Wokwi: confira na serial a linha RSSI ... dBm = ... mW a cada 2 s e os pontos chegando no painel.
  2. Na bancada: troque SIMULADOR para 0, preencha a rede da sala e grave no ESP32 do kit.
  3. Percorra os cinco pontos do seu percurso, parando em cada um tempo suficiente para o painel registrar várias leituras.
  4. No elevador, fique pelo menos cinco segundos com as portas fechadas e depois saia. O painel deve mostrar a lacuna na série e o status offline.
  5. Versione no repositório o sketch.ino, o diagram.json, o link do projeto no Wokwi, a tabela da etapa Confrontar e uma captura do painel.

A plataforma online da ponderada depende do broker de sala, ainda não definido entre Ubidots, Adafruit IO e Raspberry Pi local (pendência P7). Até a definição, o painel deste acervo, ligado ao broker público broker.hivemq.com, faz o papel de plataforma com gráfico contínuo de tempo por dBm. O broker é público: publique só o RSSI.

6. Comprovar

Sem consultar a IA, responda no PROCESSO.md:

  1. Leia dois valores que você mediu e diga quantas vezes a potência de um é maior que a do outro.
  2. O que representa uma queda de 3 dB em potência?
  3. Por que o painel sabe que o rastreador sumiu, se o rastreador não consegue avisar de dentro do elevador?

7. Desafio: alerta de última comunicação

No conjunto fictício de dados/, as leituras de cada ciclo chegam de 7 em 7 dias, sem exceção. Na sua cópia do painel, acrescente à tabela de ciclos abertos um alerta quando a última comunicação passa de 8 dias. Mude a data de referência para conferir que o alerta acende, e escreva no PROCESSO.md por que o limiar é maior que o intervalo das leituras.
