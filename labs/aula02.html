Laboratório: o lacre do rastreador conta cada violação uma única vez

O TAPI da Cerradinho pede que o rastreador detecte a retirada ou o rompimento do lacre e registre o evento. Aqui o lacre é um botão: cada aperto é um rompimento. O contato metálico quica, e sem tratamento um único rompimento vira vários alarmes. O laboratório roda no Wokwi, que simula o bounce do botão, e segue as cinco etapas do 5C no seu PROCESSO.md.

1. Abrir o projeto no Wokwi

  1. Abra wokwi.com/projects/new/arduino-uno.
  2. Na aba diagram.json, apague tudo e cole o circuito abaixo: botão do lacre no pino 2, LED de status no pino 8 e buzzer no pino 9.
  3. Na aba sketch.ino, apague tudo e cole o código abaixo.
  4. Inicie a simulação, abra o monitor serial e aperte o botão algumas vezes.

Código (labs/aula02/sketch.ino) 

// Aula 02: lacre do rastreador da Cerradinho modelado como chave.
// Cada aperto do botão representa um rompimento do lacre. O contato quica
// (bounce), então o firmware só aceita a mudança depois de 20 ms estável.
// Na serial: toques brutos lidos no pino e violações confirmadas.
const int PINO_LACRE = 2;                    // botão até o GND, com pull-up interno
const int PINO_LED = 8;                      // LED de status da Aula 01
const int PINO_BUZZER = 9;
const unsigned long JANELA_DEBOUNCE_MS = 20;

int leituraAnterior = HIGH;
int estadoEstavel = HIGH;
unsigned long ultimaMudancaMs = 0;
unsigned long toquesBrutos = 0;
unsigned long violacoes = 0;

void setup() {
  pinMode(PINO_LACRE, INPUT_PULLUP);
  pinMode(PINO_LED, OUTPUT);
  pinMode(PINO_BUZZER, OUTPUT);
  Serial.begin(9600);
  Serial.println("Rastreador pronto. Aperte o botão para simular a violação do lacre.");
}

void loop() {
  int leitura = digitalRead(PINO_LACRE);

  if (leitura != leituraAnterior) {          // o contato mudou, talvez por bounce
    ultimaMudancaMs = millis();
    if (leitura == LOW) toquesBrutos++;
    leituraAnterior = leitura;
  }

  bool estavel = millis() - ultimaMudancaMs >= JANELA_DEBOUNCE_MS;
  if (estavel && leitura != estadoEstavel) { // mudança confirmada
    estadoEstavel = leitura;
    if (estadoEstavel == LOW) {
      violacoes++;
      tone(PINO_BUZZER, 2000, 200);
      Serial.print("Violação ");
      Serial.print(violacoes);
      Serial.print(" | toques brutos até agora: ");
      Serial.println(toquesBrutos);
    }
  }

  digitalWrite(PINO_LED, estadoEstavel == LOW ? HIGH : LOW);
}

O Wokwi simula o bounce do botão, mas não simula a carga de um capacitor. A curva do circuito RC da ponderada é medida na bancada, com o kit em sala, e a animação carga-rc do material de apoio ajuda a prever o resultado.

2. Contextualizar

Antes de mexer no código, escreva no PROCESSO.md:

  • o objetivo: cada rompimento do lacre gera exatamente um alarme;
  • o comportamento esperado: dez apertos produzem dez violações na serial, com o número de toques brutos maior que dez;
  • o critério de aceitação: com a janela de 20 ms, violações iguais ao número de apertos em três rodadas de dez;
  • o que você pretende delegar à IA e o que pretende fazer sozinho.

3. Consultar

Faça ao Gemini uma pergunta delimitada, que peça explicação ou hipótese sobre um ponto que você não domina. Exemplos:

  • "Por que um botão mecânico gera vários pulsos num único aperto?"
  • "Que janela de debounce costuma ser usada para botões de contato, e de onde sai esse valor?"

Registre a pergunta exatamente como você fez e a resposta resumida.

5. Construir

Versione no repositório do grupo o sketch.ino, o diagram.json, o link do projeto salvo no Wokwi, a tabela da etapa Confrontar e uma captura do monitor serial.

6. Comprovar

Sem consultar a IA, responda no PROCESSO.md:

  1. Por que, com INPUT_PULLUP, o botão apertado lê LOW?
  2. Com a janela em 200 ms, o que acontece se o lacre for rompido duas vezes em 100 ms?
  3. Por que o código usa millis() e não delay() para esperar a janela?

7. Desafio: retirada autorizada

O TAPI pede um fluxo de retirada autorizada do lacre durante o reparo. Acrescente um segundo botão, "autorizar", no pino 3. Depois de apertá-lo, o próximo rompimento em até 10 s é registrado na serial como retirada autorizada, sem buzzer; fora dessa janela, continua sendo violação.
