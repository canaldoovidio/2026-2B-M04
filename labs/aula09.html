Laboratório: o relé remoto só dispara depois da confirmação humana

O TAPI da Cerradinho pede alertas de permanência (referência inicial de 150 dias) e de violação do lacre, tratados por um responsável. Aqui o alerta publicado pelo rastreador arma um relé remoto via MQTT. O relé só liga quando uma pessoa publica a confirmação num segundo tópico; sem ela, a central desarma sozinha em 30 s. O laboratório roda no Wokwi e segue as cinco etapas do 5C no seu PROCESSO.md.

1. Registro do uso de IA

Comece por aqui, antes de abrir o Wokwi: crie no repositório do grupo o arquivo PROCESSO.md a partir do modelo indicado abaixo. Cada etapa do 5C deste roteiro pede um registro nesse arquivo, que você preenche à medida que avança.

Use os modelos do acervo: PROCESSO.md, com as cinco etapas, e ADR de uso de IA, com uma sugestão da IA que você rejeitou ou corrigiu. O candidato natural desta aula é o código de disparo gerado pelo Gemini.

2. Segurança elétrica

Um módulo relé consegue chavear cargas ligadas à rede elétrica de 127 V ou 220 V, e o autoestudo "Módulos Relé com ESP32" mostra isso. Nenhuma montagem desta aula usa tensão de rede, nem no Wokwi nem na bancada. A carga do laboratório é um LED alimentado pelo próprio ESP32. Trabalho em instalação elétrica de rede é regulado pela NR-10 do Ministério do Trabalho e Emprego e fica fora do escopo do módulo.

Na bancada, confira a lógica do seu módulo antes de ligar qualquer carga: muitos módulos com optoacoplador são ativos em nível baixo, ao contrário do relé do Wokwi, e entre o reset e o setup o GPIO do ESP32 fica flutuando. O estado seguro depende dessa lógica, e a defesa de hardware é um resistor de pull na entrada IN que segure o relé desligado.

3. Abrir o projeto no Wokwi

  1. Abra wokwi.com/projects/new/esp32.
  2. Na aba diagram.json, apague tudo e cole o circuito abaixo: botão do lacre no GPIO 4, entrada IN do relé no GPIO 26, LED amarelo de "armado" no GPIO 27, LED vermelho no contato NO (a carga) e LED verde no contato NC (repouso).
  3. Na aba Library Manager, clique em "+" e adicione PubSubClient: o Wokwi cria o libraries.txt com a lista abaixo.
  4. Na aba sketch.ino, apague tudo, cole o código abaixo e troque dupla00 pelo código da sua dupla. O broker é público: duas duplas com o mesmo prefixo disparam o relé uma da outra.
  5. Conecte e assine o cliente HiveMQ antes de iniciar a simulação (passo a passo em "Como publicar a confirmação", abaixo). O alerta de permanência sai uma vez só por simulação, e quem assinar depois não o recebe.
  6. Inicie a simulação e abra o monitor serial. O relógio simulado anda um dia por segundo a partir de 140 dias, e o alerta sai quando os dias fora passam do limiar: no 151.º dia, cerca de 11 s depois de o rastreador conectar ao broker.

Código (labs/aula09/sketch.ino) 

// Aula 09: disparo remoto de atuador com confirmação humana.
// O rastreador publica um alerta (permanência acima de 150 dias ou violação do
// lacre). A central assina o alerta, arma o relé e espera uma confirmação
// humana num segundo tópico. Sem confirmação em 30 s, desarma sozinha.
// Neste laboratório o mesmo ESP32 faz os dois papéis, rastreador e central,
// e a mensagem passa de verdade pelo broker. A carga é um LED: nenhuma
// montagem desta aula usa tensão de rede.
#include <WiFi.h>
#include <PubSubClient.h>

// Troque dupla00 pelo código da sua dupla: o broker é público e compartilhado.
#define PREFIXO "cerradinho/dupla00/DV-01/"
const char* TOPICO_ALERTA = PREFIXO "alerta";
const char* TOPICO_CONFIRMACAO = PREFIXO "confirmacao";
const char* TOPICO_ESTADO = PREFIXO "estado";
const char* BROKER = "broker.hivemq.com";    // P7: broker de sala ainda não definido
const int PORTA = 1883;

const int PINO_LACRE = 4;                    // botão até o GND, com pull-up interno
const int PINO_RELE = 26;                    // entrada IN do módulo relé
const int PINO_ARMADO = 27;                  // LED amarelo: aguardando confirmação
const int RELE_LIGADO = HIGH;                // relé "npn" do Wokwi: HIGH liga COM ao NO
const int RELE_DESLIGADO = LOW;

const int LIMIAR_DIAS = 150;                 // referência inicial do TAPI, configurável
const int DIAS_FORA_INICIAL = 140;           // ciclo fictício, perto do limiar
const unsigned long MS_POR_DIA = 1000;       // relógio acelerado: 1 s = 1 dia
const unsigned long JANELA_CONFIRMACAO_MS = 30000;
const unsigned long JANELA_DEBOUNCE_MS = 20;
const unsigned long INTERVALO_CONEXAO_MS = 2000;

enum Estado { MONITORANDO, ARMADO, DISPARADO };
Estado estado = MONITORANDO;

WiFiClient rede;
PubSubClient mqtt(rede);

int diasFora = DIAS_FORA_INICIAL;
unsigned long ultimoDiaMs = 0;
bool alertaPermanenciaEnviado = false;
unsigned long proximoId;                     // sorteado no setup: não repete entre boots
unsigned long idArmado = 0;
unsigned long armadoDesdeMs = 0;
unsigned long ultimaTentativaMs = 0;

int leituraAnterior = HIGH;
int lacreEstavel = HIGH;
unsigned long ultimaMudancaMs = 0;

void publicarEstado(const char* texto) {
  mqtt.publish(TOPICO_ESTADO, texto);
  Serial.print("Estado: ");
  Serial.println(texto);
}

void publicarAlerta(const char* motivo) {
  char mensagem[96];
  snprintf(mensagem, sizeof(mensagem), "{\"id\":%lu,\"motivo\":\"%s\",\"dias_fora\":%d}",
           proximoId++, motivo, diasFora);
  mqtt.publish(TOPICO_ALERTA, mensagem, false);  // sem retain
  Serial.print("Rastreador publicou: ");
  Serial.println(mensagem);
}

void voltarAMonitorar(const char* motivo) {
  estado = MONITORANDO;
  digitalWrite(PINO_RELE, RELE_DESLIGADO);
  digitalWrite(PINO_ARMADO, LOW);
  mqtt.unsubscribe(TOPICO_CONFIRMACAO);
  publicarEstado(motivo);
}

void tratarAlerta(const String& texto) {
  if (estado != MONITORANDO) return;         // já há um alerta em tratamento
  int posicao = texto.indexOf("\"id\":");
  if (posicao < 0) return;
  idArmado = texto.substring(posicao + 5).toInt();
  armadoDesdeMs = millis();
  estado = ARMADO;
  digitalWrite(PINO_ARMADO, HIGH);
  mqtt.subscribe(TOPICO_CONFIRMACAO);        // só escuta confirmação depois de armar
  char aviso[96];
  snprintf(aviso, sizeof(aviso), "armado: publique CONFIRMAR %lu em até 30 s", idArmado);
  publicarEstado(aviso);
}

void tratarConfirmacao(const String& texto) {
  if (texto == "DESLIGAR") {
    if (estado == DISPARADO) voltarAMonitorar("desligado pelo operador");
    return;
  }
  bool noPrazo = millis() - armadoDesdeMs < JANELA_CONFIRMACAO_MS;
  if (estado != ARMADO || !noPrazo || texto != "CONFIRMAR " + String(idArmado)) {
    publicarEstado("confirmação ignorada: nenhum alerta armado com esse id no prazo");
    return;
  }
  digitalWrite(PINO_RELE, RELE_LIGADO);
  digitalWrite(PINO_ARMADO, LOW);
  estado = DISPARADO;
  publicarEstado("disparado com confirmação humana");
}

void aoReceber(char* topico, byte* dados, unsigned int tamanho) {
  String texto;
  for (unsigned int i = 0; i < tamanho; i++) texto += (char)dados[i];
  texto.trim();
  Serial.print("Central recebeu [");
  Serial.print(topico);
  Serial.print("] ");
  Serial.println(texto);
  if (strcmp(topico, TOPICO_ALERTA) == 0) tratarAlerta(texto);
  else if (strcmp(topico, TOPICO_CONFIRMACAO) == 0) tratarConfirmacao(texto);
}

void tentarConectar() {                      // uma tentativa a cada 2 s, sem travar o loop
  if (millis() - ultimaTentativaMs < INTERVALO_CONEXAO_MS) return;
  ultimaTentativaMs = millis();
  String id = "rastreador-" + String((uint32_t)esp_random(), HEX);
  Serial.print("Conectando ao broker... ");
  if (mqtt.connect(id.c_str())) {
    Serial.println("ok");
    mqtt.subscribe(TOPICO_ALERTA);
    if (estado != MONITORANDO) mqtt.subscribe(TOPICO_CONFIRMACAO);
    publicarEstado("monitorando");
  } else {
    Serial.println("falhou, nova tentativa em 2 s");
  }
}

void expirarSemConfirmacao() {
  if (estado == ARMADO && millis() - armadoDesdeMs >= JANELA_CONFIRMACAO_MS) {
    voltarAMonitorar("desarmado: a confirmação não chegou em 30 s");  // desarme automático
  }
}

void setup() {
  pinMode(PINO_RELE, OUTPUT);
  digitalWrite(PINO_RELE, RELE_DESLIGADO);   // estado seguro antes de qualquer rede
  pinMode(PINO_LACRE, INPUT_PULLUP);
  pinMode(PINO_ARMADO, OUTPUT);
  Serial.begin(115200);
  proximoId = esp_random() % 900000 + 100000;  // id de 6 dígitos, imprevisível
  WiFi.begin("Wokwi-GUEST", "", 6);
  while (WiFi.status() != WL_CONNECTED) delay(100);
  Serial.println("Wi-Fi conectado");
  mqtt.setServer(BROKER, PORTA);
  mqtt.setCallback(aoReceber);
  ultimoDiaMs = millis();
}

void loop() {
  expirarSemConfirmacao();                     // roda mesmo com o broker fora do ar
  if (!mqtt.connected()) tentarConectar();
  else mqtt.loop();

  if (millis() - ultimoDiaMs >= MS_POR_DIA) {  // passa um dia simulado
    ultimoDiaMs += MS_POR_DIA;
    diasFora++;
    Serial.print("Dias fora: ");
    Serial.println(diasFora);
    if (diasFora > LIMIAR_DIAS && !alertaPermanenciaEnviado) {
      alertaPermanenciaEnviado = true;
      publicarAlerta("permanencia");
    }
  }

  int leitura = digitalRead(PINO_LACRE);       // debounce da Aula 02
  if (leitura != leituraAnterior) {
    ultimaMudancaMs = millis();
    leituraAnterior = leitura;
  }
  if (millis() - ultimaMudancaMs >= JANELA_DEBOUNCE_MS && leitura != lacreEstavel) {
    lacreEstavel = leitura;
    if (lacreEstavel == LOW) publicarAlerta("lacre");
  }
}

Broker público broker.hivemq.com, porta 1883, porque o broker de sala ainda não foi definido entre Ubidots, Adafruit IO e Raspberry Pi local (pendência P7 do plano de ensino). A documentação do Wokwi avisa que o tráfego do gateway público é monitorado e não deve levar dado privado: os tópicos usam só o identificador fictício DV-01.

Como publicar a confirmação

A confirmação é o papel do operador humano e sai de outro aparelho. Abra o cliente MQTT por WebSocket da HiveMQ no navegador, troque o host para broker.hivemq.com, mantenha a porta 8884, deixe a opção SSL/TLS ativada (a porta 8884 é WebSocket com TLS) e conecte. Assine cerradinho/dupla00/DV-01/# com o seu prefixo e acompanhe o alerta e o estado. Para disparar, publique no tópico cerradinho/dupla00/DV-01/confirmacao a mensagem CONFIRMAR seguida do id que veio no alerta, por exemplo CONFIRMAR 516751. O id tem seis dígitos e é sorteado a cada boot da placa, então uma confirmação guardada de uma simulação anterior não vale na seguinte. A central só assina o tópico de confirmação depois de armar. Para desligar o relé disparado, publique DESLIGAR.

4. Contextualizar

Antes de mexer no código, escreva no PROCESSO.md:

  • o objetivo: um alerta de permanência ou de lacre aciona o atuador remoto só depois de uma pessoa confirmar;
  • quem é essa pessoa na Cerradinho: o TAPI diz que os alertas são tratados por um responsável e pede que o projeto defina quem trata cada alerta;
  • o comportamento esperado em três cenários: confirmação certa em até 30 s, confirmação com o id errado e nenhuma confirmação;
  • o critério de aceitação: em dez alertas, o relé liga só nos confirmados, nunca fica armado por mais de 30 s e sempre começa desligado depois de reiniciar a placa;
  • o que você pretende delegar à IA e o que pretende fazer sozinho.

  • "O que acontece com uma mensagem publicada com a flag retain quando um dispositivo se reconecta ao broker?"
  • "Gere um sketch para ESP32 que ligue um relé quando chegar uma mensagem MQTT." Guarde o código: ele é o material do Confronto com a IA.

Registre a pergunta exatamente como você fez e a resposta resumida.

6. Confrontar

Duas conferências, cada uma com a evidência anotada.

  1. O código da IA dispara sem confirmação? Procure no sketch gerado pelo Gemini cada digitalWrite que liga o relé e diga qual mensagem leva até ele. Se uma mensagem de alerta, ou qualquer mensagem no tópico, liga o relé direto, o código dispara sem confirmação humana. Compare com o tratarConfirmacao do laboratório, o único lugar que liga o relé.
  2. O relé do Wokwi liga em HIGH? A documentação do wokwi-relay-module se contradiz: a tabela de atributos diz que o padrão "npn" é ativo em nível alto, e o parágrafo de operação diz que IN em nível alto liga COM ao NC. O acervo conferiu no simulador em 13/10/2026, rodando wokwi.com por Playwright e lendo o estado dos LEDs no diagrama: com "npn", IN em HIGH acende o LED do NO, e IN em LOW ou ainda sem pinMode acende o do NC; com "pnp", o contrário. Vale a tabela. Confira você também: confirme o alerta e anote qual LED acende, o vermelho (NO) ou o verde (NC).

9. Desafio: o relé desarma sozinho

Hoje, depois de disparado, o relé fica ligado até alguém publicar DESLIGAR. Mude o firmware para que o atuador desarme sozinho se a confirmação não chegar em 30 segundos: com o relé ligado, o operador precisa publicar de novo CONFIRMAR com o mesmo id a cada 30 s, e a falta dessa renovação desliga o relé e publica o estado. É o mesmo princípio do pedal de homem-morto de um trem: a carga só continua ligada enquanto alguém confirma que está presente.
